# 概念解释模板规则

## 用途

用于解释“一个概念是什么、有什么特点、为什么与观众有关”。不承担完整逐字稿，只展示核心概念、简短定义和关键词。

## 构图选择

### 中心放射型 `radial`

适合一个概念对应 2～4 个并列特征。核心概念必须最先出现，外围解释随后围绕它展开。

调用合成项：`ConceptExplainerRadialGithub`。

### 上下拆解型 `topdown`

适合“概念 → 定义 → 组成或特征”的层级解释。它不是流程，不使用步骤序号。

调用合成项：`ConceptExplainerTopDownGithub`。

## 输入内容

- 核心概念：例如 `GitHub`。
- 一句话定义：例如“全球开源代码和项目托管平台”。
- 2～4 个解释关键词。
- 如需数字高亮，将数字拆成前缀、高亮值和后缀。

## 共同规则

- 核心概念必须最先出现。
- 空白贴纸先进入，文字随后单独贴入；文字不能烘焙在贴纸图片中。
- 文字以最上层承载文字的纸张为中心，不以整组衬纸边界为中心。
- 每张贴纸拥有独立文字安全区，不能跨贴纸复用同一个纵坐标。
- 箭头必须连接真实信息关系，并逐一检查起点与终点。
- 文字变长时只允许缩小字号，不能移动中心或拉伸贴纸。
- 两种构图的具体坐标、箭头方向和安全区见 `layout.json`。

## 动效顺序

### 中心放射型

核心贴纸 → 核心文字 → 定义 → 左侧解释 → 右侧解释 → 底部结论。

### 上下拆解型

顶部概念 → 中间定义 → 三个分支箭头 → 底部三个解释贴纸及文字。

## 调用

```powershell
npm.cmd run render:concept-radial-github
npm.cmd run render:concept-topdown-github
```

实际使用时修改 `src/Root.tsx` 中对应合成项的文字参数，或复制为新的配置入口；不得修改贴纸坐标。

## 验收

- 第一眼能明确看出核心概念。
- 上下拆解型三支箭头分别指向左、中、右三个目标。
- 所有文字位于米白纸或黑色标题纸正中心。
- 底层碎纸完整，没有裁切和方形背景。
- 画面有明显留白，不得把所有贴纸挤成一团。
