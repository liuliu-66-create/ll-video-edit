# ll-video-edit

把已经定稿的逐字稿制作成“完整配音＋单行字幕＋动效模板/插画＋真实录屏”的教程视频。用户负责提供内容、真实素材和关键确认；Codex 负责判断、制作、检查与交付。

## 启动规则

开始新项目时，先完整阅读 [references/six-step-workflow.md](references/six-step-workflow.md)，再执行任何操作。

第一条回复只能问：

> 这条视频请选择一种画幅：16:9 横屏，还是 9:16 竖屏？

不要先检查环境，不要先问平台、选题、目标时长、风格或素材。用户确认画幅后，只请求已经定稿的逐字稿；不写稿、不改稿。

恢复已有项目时，先读取项目中的 `project-status.json` 和已有交付物，确定最后一个“用户已确认”的步骤。不要把“已经生成”或“技术检查通过”当成“用户已确认”。

## 不可跳过的规则

- 严格按六步顺序推进；当前步骤没有达到完成标准且未经用户确认，不进入下一步。
- 能从逐字稿、音频和素材判断的信息由 Codex 主动判断，不反问用户总结。
- 每个确认节点先提供可查看的文档、图片或带声音视频，再请求确认。
- 字幕始终来自完整定稿逐字稿；画面关键词由 Codex 提炼，不能把整句字幕重复搬到画面主体。
- 真实软件操作只使用用户提供的真实录屏或截图，不生成虚假软件界面。
- 用户提交真实素材前自行处理隐私；不要擅自打码、模糊、裁切或改变隐私范围。
- 已确认的静态设计和动态样片不重做；全片只补齐未完成镜头。
- 每次导出后先做技术检查和实际画面检查，再向用户汇报。
- 不要求人物口播原片。第一步输入是定稿逐字稿和最终配音；真实录屏在第三步按素材清单准备。

## 项目与环境

用户提交定稿逐字稿后，再运行 `scripts/check_environment.ps1` 检查 Node.js、npm、FFmpeg、ffprobe、Python 和动效素材库。缺失项逐项说明，不让用户猜。

需要新建项目目录时运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/init_project.ps1 -ProjectPath "<项目绝对路径>" -AspectRatio "16:9"
```

不得覆盖已有 `project-status.json`。每完成一个确认节点，更新状态文件中的当前步骤、交付物路径和确认状态。

## 动效素材库

进入第四步、需要选择现成模板时，阅读 [references/motion-library.md](references/motion-library.md)。只调用 `library.json` 中状态为 `validated` 的模板；预览视频只用于挑选，不能作为固定素材剪入成片。

如果没有找到素材库，可以先完成前三步；进入第四步前必须明确指出缺失，并请用户提供素材库路径。不得假装已经调用模板。

## 导出与验收

制作静态效果图、动态样片、完整初版或最终成片前，阅读 [references/qa-checklist.md](references/qa-checklist.md)。

最终只能在以下条件全部满足后宣布完成：

1. 用户已经确认最终画面内容；
2. 视频、音频、字幕、时长和关键画面已实际检查；
3. 完整 MP4、可继续编辑的 Remotion 工程和验收结果都已交付。
