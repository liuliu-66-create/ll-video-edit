# ll-video-edit

把定稿逐字稿或已录人物口播视频制作成“单条口播声音＋单行字幕＋动效模板/插画＋真实录屏”的教程视频。逐字稿模式生成配音；口播视频模式保留原声，人物全程以小窗出现。用户提供内容、真实素材并完成关键确认；Codex 负责规划、制作、检查与交付。

## 启动规则

开始新项目时，先完整阅读 [references/six-step-workflow.md](references/six-step-workflow.md)。收到人物口播视频或进入该模式时，再完整阅读 [references/talking-head-mode.md](references/talking-head-mode.md)；逐字稿模式不加载视频模式细则。

新项目固定 16:9。根据用户已给材料直接判断输入模式，不额外让用户选择：

- 只有定稿逐字稿：沿用逐字稿模式；未给内容时请用户提供定稿逐字稿或已录口播视频。
- 只有带原声人物口播视频：进入口播视频模式，先检查原片并生成待核对转写稿；不要求重新配音。
- 两者都有：先核对逐字稿与视频实际口播；不默默把不一致的稿当字幕或擅自改口播。

不要重复询问画幅、平台、选题、目标时长或已提供的材料；不写稿、不改稿、不自动剪口误。输入模式确定后按对应第一步检查环境与素材。

恢复已有项目时，先读取项目中的 `project-status.json` 和已有交付物，确定最后一个“用户已确认”的步骤。旧项目缺少 `inputMode` 时根据已确认输入判断，不重建或覆盖状态；不能判断时才询问。不要把“已经生成”或“技术检查通过”当成“用户已确认”。

制作前读取项目已确认的视觉配置和用户品牌规范，按 `six-step-workflow.md` 的“项目视觉配置”记录并全片复用；用户已有明确偏好不重复询问。局部纠正后检查全片同类问题。

素材清单必须让用户能直接照着准备；口播指向具体 Skill、页面或操作结果时，分镜要标明对应的真实素材及出现时间。第四步确认的风格适用于所有相关镜头与转场，导出后按 `qa-checklist.md` 对照最终 MP4 检查。

## 不可跳过的规则

- 严格按六步顺序推进；当前步骤没有达到完成标准且未经用户确认，不进入下一步。
- 能从逐字稿、音频和素材判断的信息由 Codex 主动判断，不反问用户总结。
- 每个确认节点先提供可查看的文档、图片或带声音视频，再请求确认。
- 逐字稿模式的字幕来自完整定稿逐字稿；口播视频模式的字幕来自用户核对后的实际口播转写，并对齐原声。画面关键词由 Codex 提炼，不能把整句字幕重复搬到画面主体。
- 真实软件操作只使用用户提供或明确授权获取的真实录屏或截图，记录来源，不生成虚假软件界面。
- 用户提交真实素材前自行处理隐私；不要擅自打码、模糊、裁切或改变隐私范围。
- 已确认的静态设计和动态样片不重做；全片只补齐未完成镜头。
- 当用户关注样片确认后的成片耗时，在第六步阅读 [references/fast-full-video.md](references/fast-full-video.md)，复用已确认的样片源码，减少剩余镜头的重复搭建，并分别记录制作、渲染、验收及等待用户的时间。提速不能省略确认或画面检查，也不能把提前完成的工作从总耗时中隐去。
- 每次导出后先做技术检查和实际画面检查，再向用户汇报。
- 分镜按信息变化安排画面，明确数字、步骤与关系必须完整对应口播；模板次数通过不代表内容与节奏通过。全片交付前按 `qa-checklist.md` 单独完成内容与节奏检查。
- 逐字稿模式不要求人物口播原片；口播视频模式必须保留原声与全程人物小窗，不切成真人主画面。动效主体在 16:9 画面中保持居中，不能为躲小窗缩放、平移模板或改动模板元素。
- 真实操作只使用真实录屏或截图。小窗与关键操作冲突时，先在右上角缩小小窗，用实际素材出静态合成图请用户确认；仍遮挡时提供替代布局，不擅自换角或遮住操作。

## 项目与环境

用户提交定稿逐字稿或口播视频后，再运行 `scripts/check_environment.ps1` 检查 Node.js、npm、FFmpeg、ffprobe、Python 和动效素材库；口播视频模式另检查转写是否可执行。缺失项逐项说明，不让用户猜。

需要新建项目目录时运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/init_project.ps1 -ProjectPath "<项目绝对路径>"
```

不得覆盖已有 `project-status.json`。识别输入后把 `inputMode` 记为 `script` 或 `talking_head`，记录原稿或原视频路径；`confirmed.step1_audio` 在两种模式中均表示“文字与最终声音已获确认”。每完成一个确认节点，更新当前步骤、交付物路径和确认状态。

## 动效素材库

第二步规划分镜时就阅读 [references/motion-library.md](references/motion-library.md) 和 [references/storyboard-usage.md](references/storyboard-usage.md)，预选动效并逐镜计数、附全片汇总。次数检查未完成或未通过，不进入制作。第四步更换模板后重新统计。只调用 `library.json` 中状态为 `validated` 的模板；预览视频只用于挑选，不能作为固定素材剪入成片。

如果没有找到素材库，可以完成第一步并整理分镜和素材需求草案，但动效选择与计数须标记待完成；请用户提供素材库路径，补齐统计后再正式确认分镜。不得假装已经调用模板或统计通过。

### 快速制作与模板晋级

默认目标是尽快完成当前视频，不是边剪视频边扩建素材库。遇到现有模板无法覆盖的镜头时，按以下顺序处理：

1. 语义匹配的 validated 模板：直接调用并按分镜计数。
2. 现有背景、纸张、人物、钱币、字体或基础组件能够组合：先在分镜中标记“非素材库画面”并取得用户确认，再在当前视频工程中制作单次画面。
3. 只缺一张插画或装饰素材：只补该素材并用于当前镜头，不先开发模板。
4. 只有用户明确要求扩充素材库，或同一结构已经在不同项目中重复出现并证明值得复用时，才进入模板开发、参数化、边界测试和 library.json 登记。

单次画面仍须经过静态确认、动态确认和成片检查，但不要求创建 TEMPLATE.md、layout.json、通用预设或最大数量测试。不得为了降低计数把真实的完整模板伪装成单次组合；也不得因为写了一个 Remotion 组件就自动把它升级为素材库模板。

## 导出与验收

制作静态效果图、动态样片、完整初版或最终成片前，阅读 [references/qa-checklist.md](references/qa-checklist.md)。

最终只能在以下条件全部满足后宣布完成：

1. 用户已经确认最终画面内容；
2. 视频、音频、字幕、时长和关键画面已实际检查；
3. 完整 MP4、可继续编辑的 Remotion 工程和验收结果都已交付。
