# 分镜动效计数（第二步必读）

## 必交内容
每次提交分镜（含修订版），逐镜列出模板名称、具体变体/Composition、family、layoutPattern、该动效本片第几次使用。
表尾必须列出每个具体动效、家族、构图的总次数及镜头编号，标明超限与相邻重复。未使用素材库的镜头也保留，写“非素材库画面”，不能省略而误判相邻关系。

## 计数口径
- 一次完整调用计一次；一镜头调用两个模板要列两项；同模板重新入场独立调用两次也计两次。
- 同一次调用内部的节点、文字、循环帧、照片或钱币数量不算多次。
- 具体动效按模板ID＋Composition统计；同家族的不同变体仍合并统计family。
- family和layoutPattern从真实library.json读取，禁止自填新名称规避规则。
- 嵌套变体有独立family/layoutPattern时优先使用；没有则继承父项，保守合并统计，不凭变体名字猜不同构图。
- 真正不属于完整模板的公共背景、字体等基础组件不算完整模板调用；不能把完整模板改称“自定义组合”逃避计数。
- 为当前视频临时编写、未登记进 `library.json` 的单次构图属于“非素材库画面”，即使它使用 Remotion 组件也不自动算作模板；它只做当前镜头需要的确认和验收。
- 发现结构缺口时默认先做单次画面，不自动开发模板。只有用户明确要求扩库，或同一结构已在不同项目重复出现并证明值得复用时，才晋级为模板。
- 默认家族最多3次、同构图最多2次，相邻镜头不重复同一家族；以素材库selectionPolicy为准。
- 超限先调整分镜，不为降低次数把内容硬套不合适模板。
- 缺少素材库或尚未选定模板时标记“待选/未完成统计”，不编造ID或0次，不宣称通过；正式确认分镜前补齐。

## 执行
Codex生成按时间顺序排列的storyboard-usage.json，与完整分镜逐项对应，不让小白手填JSON：
```json
{
  "shots": [
    {"id": "S01", "kind": "library", "uses": [
      {"templateId": "process-flow-zigzag", "composition": "ProcessFlowZigzag"}
    ]},
    {"id": "S02", "kind": "other", "uses": []},
    {"id": "S03", "kind": "library", "uses": [
      {"templateId": "process-flow-journey", "composition": "ProcessFlowJourney"}
    ]}
  ]
}
```

运行scripts/check_template_usage.py --plan <分镜JSON> --library <library.json> --out <新统计报告.md>。
Python退出码0表示次数检查通过；1表示超限/相邻重复；2表示输入或素材库错误。非0均不可进入制作。
报告拒绝覆盖已有文件；修改分镜后使用新版本报告路径。将报告逐镜列合入分镜表，完整汇总附在表末，不能只给一个“检查通过”结论。
第二步交付前、第四步换模板后、第六步渲染前都重新统计；正式渲染前对照实际组件调用，不能拿旧分镜报告替代实际使用情况。
脚本只核查声明的调用，不会自动识别视频或源码中漏报的调用；Codex负责核对完整性、语义和时间顺序。
