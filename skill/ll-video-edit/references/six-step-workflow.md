# 六步执行流程

这是 `ll-video-edit` 的内部执行真源。一次只推进当前步骤；每一步先完成交付物和检查，再取得用户确认。

## 项目视觉配置

制作前按当前用户指示、项目已确认配置、用户品牌规范的顺序确定视觉设置。当前本地用户六六的品牌 Logo 默认左上角；此项为个人偏好，不是所有使用者的通用规则。人物小窗默认右上角，字幕单行无背景；用户本次明确指示优先。

在 `project-status.json` 中增量保存 `visualConfig`：Logo 素材路径与位置、人物小窗位置与尺寸、字幕样式、背景、字体及配置依据；未确定项记为待定，不把默认值当作已确认。第四步确认后记录确认范围，所有镜头共用同一配置。恢复项目先读取配置，旧项目缺字段时从已有确认记录补齐，不覆盖原状态。

同时记录已确认风格的适用范围，逐镜覆盖背景、文字画面、截图与真实录屏的呈现、转场；例外也要有用户确认依据。若当前项目确认“除人物小窗外全片撕纸风格”，上述画面均沿用撕纸视觉，不中途混入普通卡片。此例仅适用于确认该风格的项目，不作为所有项目的默认风格。

收到局部反馈时检查全片同类问题；在状态文件 `revisionScope` 中记录用户要求、受影响镜头、修正结果及待确认内容。已获授权的修改直接执行，同类检查不扩大为无关重设计；涉及新的布局选择时使用原有确认节点，不新增重复确认流程。

## 第一步：确认文字和最终声音

1. 新项目固定使用 `16:9` 横屏。用户已给逐字稿或口播视频时直接识别输入模式；未给时只请求这两类材料之一，不额外询问画幅、平台或选题。
2. **逐字稿模式**：检查定稿逐字稿是否读取完整；不引导写稿、不改稿。使用火山引擎豆包语音把整篇逐字稿生成一条连续配音；首次使用时引导用户完成本机密钥配置，不让用户在聊天中粘贴密钥。短文稿整篇合成；超出接口限制时由 Codex 统一参数分段并合并。优先输出 `audio/vo-full.wav`（44100Hz、单声道），用 ffprobe 检查真实时长和内容。确认后若改稿，必须重新配音。
3. **口播视频模式**：按 [talking-head-mode.md](talking-head-mode.md) 检查原片视频、原声音轨和比例；转写实际口播并交用户核对，未经确认的自动转写只是草稿。保留原声，不调用配音服务，也不擅自删除停顿、口误或改写内容。视频和稿件同时提供时，先标出不一致并确认以实际口播为准的字幕文本。
4. 记录输入模式、最终文字、最终声音来源及真实时长；后续字幕与镜头时间轴只基于这份已确认输入。

完成标准：已确认的完整文字与最终声音都齐备；逐字稿模式使用已确认配音，口播视频模式使用已确认原声。真实时长来自媒体检查，不按字数估算。

## 第二步：音频对齐和分镜表

1. 读取第一步确认的完整文字和最终声音；口播视频模式还读取原片画面。
2. 使用 ffprobe 获取准确时长；使用 Whisper 或当前可用的对齐工具生成短语级起止时间，不按字数平均估算。
3. 按信息变化拆镜头：口播出现新对象、步骤、关系、结果或操作任务时，安排对应画面变化；可切镜头、展开节点、突出关键词或推进真实操作。不把每句字幕机械变成一张图片，也不因属于同一话题就合并成长镜头；不得重复播放入场动画凑变化。
4. 为每个镜头判断画面任务：真实操作、截图/结果证明、概念解释、步骤/要点总结、开头或结尾。
5. 主动提炼短画面关键词；关键词只负责强调，不重复完整字幕。
6. 输出短语级时间轴、完整分镜表和素材需求草案。分镜表至少包含：镜头编号、时间、完整字幕、画面任务、画面类型、画面关键词、所需素材；口播视频模式注明该镜头是动效还是需真实操作录屏，人物小窗持续存在。使用素材库的镜头另列模板名称、具体变体、family、layoutPattern、本片第几次使用。按 `storyboard-usage.md` 执行计数，表尾附每个具体动效、家族、构图的次数与对应镜头，标出超限和相邻重复；修正后重新统计。章节过渡须列出真实章节依据，不能把并列条目编成章节。
7. 分镜表另列“新增信息”“画面如何回应”“变化时间点”；同一镜头有多个信息点时逐项记录。口播明确说两个部分、六个步骤或前后对比时，核对画面数量、顺序与关系完整；未逐项口播的条目只从已确认内容中取，不自行编造。安排全部展开后的阅读时间。
   口播点名具体 Skill、软件页面、操作动作或结果时，标明对应的真实截图或录屏、出现时间及素材状态。已确认的素材由 Codex 获取时记来源；缺素材时列入第三步需求，不能以抽象动效代替应展示的对象。只作顺带提及时可使用已确认的相关画面，在分镜写明处理方式。
8. 检查同一画面约 6–8 秒没有新增信息或有效操作的区间，尤其是开头 15 秒。此阈值是检查提醒，不是强制切镜头：真实演示、复杂图解或有意停留可以保留，在分镜注明观看任务；口播已进入新信息而画面滞留时须修正。
9. 将三个交付物一次性交给用户确认；此时不制作图片或视频。

完成标准：每段口播都有准确时间和对应画面，信息变化有落点，明确数量与关系表达完整，长停留已检查；逐镜动效计数与汇总齐全且检查通过；分镜、关键词及素材需求已获用户确认。素材库未就绪只能提交待完善草案，不宣称统计通过。

## 第三步：真实素材包

1. 根据已确认分镜，生成可直接执行的逐项素材清单。每项写明对应镜头、要提供的内容或已有文件路径、获取方及状态（待提供／已有／无需提供）；已有素材不重复索取，无需用户提供的内容说明由 Codex 如何取得或制作。口播视频模式将已提供原片标为已有素材。
2. 每段录屏写清软件/网页与具体页面、从哪个可辨认状态开始、按顺序执行哪些操作、画面必须出现什么、录到哪个结果或状态结束，以及建议尺寸和时长。用户拿到清单后应能直接照着录，不以“录制操作过程”等笼统描述代替。
3. 录屏优先 1920×1080 或更高；所有素材保持等比缩放，不为凑尺寸拉伸。
4. 截图优先 PNG，并注明整页、窗口全貌或局部。
5. 同时列出产品 Logo、品牌 Logo、账号名称、人物/IP参考图、原始图片、数据图或结果页。
6. 用户录制和整理素材，并在提交前自行处理隐私。
7. 检查素材是否齐全、可读取且与分镜相符；不替用户重新决定隐私范围。若真实操作镜头缺少录屏或截图，标记为缺素材，不生成假界面；只有用户确认改成概念演示后才修改分镜。无需真实操作的镜头不额外索取录屏。

涉及个人经历、金额或纠纷时，默认使用数字视觉、概念插画和抽象结构，不要求用户提供合同、聊天记录、付款记录或法律材料。只有用户主动表示愿意展示真实材料时，才把脱敏证据加入素材清单。

完成标准：所有必要素材已经齐全、可用并获得用户确认。

## 第四步：模板选择和静态效果图

1. 读取第二步确认的分镜、关键词和第三步素材，不要求用户重复总结。
2. 按内容选择画面组合：插画＋关键词、插画＋真实录屏、关键词＋真实录屏、纯概念插画或纯关键词强调。
3. 如果存在动效素材库，按 `motion-library.md` 选择已验证模板；真实录屏、截图和结果展示也先匹配已有展示模板，分别核对素材内容与展示形式，不自行重建相似布局。没有合适模板时才提出非素材库方案，禁止硬套。
4. 先按流程、时间、循环、层级、递减、对比、列举、结论等关系类型确定模板家族，再选择具体构图；不得只因为素材库里有流程模板就把其他关系改成流程图。
5. 模板由 Codex 根据分镜主动选择，不要求用户浏览或逐个确认完整素材库；只向用户展示当前视频的结果。
6. 从全片选择两三个代表性分镜，至少覆盖插画、真实录屏、多步骤/多结果中的适用类型；口播视频模式必须包含人物小窗叠加动效的镜头，若有真实录屏，还必须包含小窗叠加实际录屏的镜头。
7. 逐张生成静态效果图，不把多个方案拼在一张图中。
8. 用户确认背景、字体、配色、插画、录屏布局、人物小窗、关键词层级和 Logo 位置；根据反馈调整并固定为全片视觉标准。真实录屏与右上小窗冲突时先缩小小窗并展示实际素材合成图；仍无法看清时给出备选方案，不能擅自换角。
   将确认的风格适用范围写入项目视觉配置；静态图至少检查纯动效、真实素材展示及转场中适用的画面，避免只用一种镜头代表全片。

视觉硬规则：

- 字幕仅一行且无背景色块；长句按真实语音拆成连续单行字幕事件。
- 所有文字在贴纸安全区内水平、垂直居中，不溢出、不贴边、不互相遮挡、不缩得过小。
- 一个贴纸优先只放一个短关键词。
- 对比画面中语义同级的文字共用字号规则：左右大标题同级同字号，左右说明小字同级同字号；逐层核对。某侧字多时先精简画面关键词或调整两侧共同布局，不单独缩小一侧。
- 动效主体在 1920×1080 画面中居中；不能为了避开人物小窗而整体缩小、平移或移动模板内元素。核心标题优先单行；需要两行时仍在贴纸内居中，不溢出。
- 所有静态效果图固定为 1920×1080，不生成其他画幅版本。
- 每次导出后实际查看成图或关键帧，不能只看代码参数。

完成标准：用户确认代表性静态效果图和视觉规则。

## 第五步：带最终声音的动态样片

1. 让用户选择样片范围：3～6 秒代表性镜头，或 10～15 秒连续样片。不要强制两种都做。
2. 从第一步确认的最终声音中截取对应时间段，不重新生成配音；口播视频模式使用原片原声。
3. 在 Remotion 中建立与成片一致的画幅、帧率和时长。
4. 合入真实录屏、插画、已确认关键词、完整字幕和品牌标识。
5. 动效以淡入、轻微位移和逐项出现为主，跟随口播含义；避免多余横线、闪光、夸张缩放和强转场。
6. 样片必须带对应最终声音；口播视频模式保持人物全程小窗，检查画面与原声同步，不能同时播放原片和小窗的两份声音。
7. 导出后用 ffprobe 检查画幅、帧率、时长和音轨；用 FFmpeg 抽取至少三张关键帧检查裁切、遮挡和画面状态。
8. 交给用户确认，根据“时间点＋问题＋希望怎么改”调整。

完成标准：用户确认带声音的动态样片，技术检查通过，可作为全片标准。

## 第六步：全片、修改和验收

1. 保留已确认样片的设计、组件和参数，只制作剩余镜头，不重新设计已通过部分；正式成片复用样片源码重新渲染，不嵌入样片 MP4。
   若用户要求压缩样片确认后的耗时，按 `fast-full-video.md` 组织剩余镜头并记录各阶段耗时。
2. 全片只使用一条从头到尾的最终口播音轨：逐字稿模式为已确认配音，口播视频模式为原片原声。人物小窗视频层静音，样片组件进入全片时也不携带独立音轨，避免双重声音。
3. 使用第二步时间轴控制镜头、字幕和关键词，在每个镜头及转场落实已确认的风格适用范围；不同内容可以使用不同构图。口播视频模式全程保留人物小窗，不出现真人主画面，也不为了小窗改动动效的居中构图。
4. 用 Remotion 导出完整初版，再用 FFmpeg 完成最终封装。
5. 用户完整观看初版，按“时间点＋具体问题＋希望如何调整”集中反馈。
6. 只修改有问题的镜头，不重做已确认部分。
7. 完成技术和视觉验收后导出交付版，并保留可继续编辑的 Remotion 工程。

完成标准：用户确认画面；Codex 确认规格、音轨、字幕、时长和关键画面正常。
