# 六步执行流程

这是 `ll-video-edit` 的内部执行真源。一次只推进当前步骤；每一步先完成交付物和检查，再取得用户确认。

## 第一步：画幅、定稿逐字稿和最终配音

1. 新任务第一句话只让用户选择 `16:9` 横屏或 `9:16` 竖屏。
2. 画幅确认后，请用户粘贴已经定稿的逐字稿或提供文件路径。
3. 检查逐字稿是否读取完整；不引导写稿、不改稿、不重新询问选题。
4. 使用火山引擎豆包语音把整篇逐字稿生成一条连续配音。首次使用时引导用户完成服务开通、音色和本机密钥配置；不要让用户在聊天中粘贴 API Key、Access Token 等密钥。
5. 短文稿整篇一次性合成；超过接口限制时由 Codex 统一参数分段并合并，禁止用户手动逐句生成后拼接。
6. 优先输出 `audio/vo-full.wav`，统一为 44100Hz、单声道。
7. 使用 ffprobe 检查音频可读性和真实时长，核对内容与定稿逐字稿相符。音频确认后若改稿，必须重新配音。

完成标准：画幅、定稿逐字稿和完整配音均已确认；真实时长来自音频检测而非估算。

## 第二步：音频对齐和分镜表

1. 读取最终逐字稿和最终配音。
2. 使用 ffprobe 获取准确时长；使用 Whisper 或当前可用的对齐工具生成短语级起止时间，不按字数平均估算。
3. 按完整语义拆镜头，不把每一句字幕机械变成一张图片。
4. 为每个镜头判断画面任务：真实操作、截图/结果证明、概念解释、步骤/要点总结、开头或结尾。
5. 主动提炼短画面关键词；关键词只负责强调，不重复完整字幕。
6. 输出短语级时间轴、完整分镜表和素材清单。分镜表至少包含：时间、完整字幕、画面任务、画面类型、画面关键词、所需素材。
7. 将三个交付物一次性交给用户确认；此时不制作图片或视频。

完成标准：每段口播都有准确时间和对应画面；分镜、关键词及素材需求已获用户确认。

## 第三步：真实素材包

1. 根据已确认分镜，生成可直接执行的素材清单。
2. 每段录屏写清软件/网页、页面、必须出现的内容、操作动作、建议尺寸、建议时长和对应分镜。
3. 横屏录屏优先 1920×1080 或更高；竖屏操作使用原生竖屏。素材保持等比缩放，不为凑尺寸拉伸。
4. 截图优先 PNG，并注明整页、窗口全貌或局部。
5. 同时列出产品 Logo、品牌 Logo、账号名称、人物/IP参考图、原始图片、数据图或结果页。
6. 用户录制和整理素材，并在提交前自行处理隐私。
7. 检查素材是否齐全、可读取且与分镜相符；不替用户重新决定隐私范围。

完成标准：所有必要素材已经齐全、可用并获得用户确认。

## 第四步：模板选择和静态效果图

1. 读取第二步确认的分镜、关键词和第三步素材，不要求用户重复总结。
2. 按内容选择画面组合：插画＋关键词、插画＋真实录屏、关键词＋真实录屏、纯概念插画或纯关键词强调。
3. 如果存在动效素材库，按 `motion-library.md` 选择已验证模板；不合适时单独设计，禁止硬套。
4. 从全片选择两三个代表性分镜，至少覆盖插画、真实录屏、多步骤/多结果中的适用类型。
5. 逐张生成静态效果图，不把多个方案拼在一张图中。
6. 用户确认背景、字体、配色、插画、录屏布局、关键词层级和 Logo 位置；根据反馈调整并固定为全片视觉标准。

视觉硬规则：

- 字幕仅一行且无背景色块；长句按真实语音拆成连续单行字幕事件。
- 所有文字在贴纸安全区内水平、垂直居中，不溢出、不贴边、不互相遮挡、不缩得过小。
- 一个贴纸优先只放一个短关键词。
- 竖屏必须重新排版，禁止直接裁切横屏设计。
- 每次导出后实际查看成图或关键帧，不能只看代码参数。

完成标准：用户确认代表性静态效果图和视觉规则。

## 第五步：带原配音的动态样片

1. 让用户选择样片范围：3～6 秒代表性镜头，或 10～15 秒连续样片。不要强制两种都做。
2. 从最终配音中截取对应时间段，不重新生成配音。
3. 在 Remotion 中建立与成片一致的画幅、帧率和时长。
4. 合入真实录屏、插画、已确认关键词、完整字幕和品牌标识。
5. 动效以淡入、轻微位移和逐项出现为主，跟随口播含义；避免多余横线、闪光、夸张缩放和强转场。
6. 样片必须带对应原配音。
7. 导出后用 ffprobe 检查画幅、帧率、时长和音轨；用 FFmpeg 抽取至少三张关键帧检查裁切、遮挡和画面状态。
8. 交给用户确认，根据“时间点＋问题＋希望怎么改”调整。

完成标准：用户确认带声音的动态样片，技术检查通过，可作为全片标准。

## 第六步：全片、修改和验收

1. 保留已确认样片，只制作剩余镜头，不重新设计已通过部分。
2. 全片只使用一条从头到尾的最终配音。若直接复用带声音样片，必须将样片静音，避免双重音轨。
3. 使用第二步时间轴控制镜头、字幕和关键词，统一已经确认的视觉和动效规则；不同内容可以使用不同构图。
4. 用 Remotion 导出完整初版，再用 FFmpeg 完成最终封装。
5. 用户完整观看初版，按“时间点＋具体问题＋希望如何调整”集中反馈。
6. 只修改有问题的镜头，不重做已确认部分。
7. 完成技术和视觉验收后导出交付版，并保留可继续编辑的 Remotion 工程。

完成标准：用户确认画面；Codex 确认规格、音轨、字幕、时长和关键画面正常。
