# ll-video-edit

给 Codex 一份定稿逐字稿，或一条已经录好的带原声人物口播视频，按六步流程完成分镜、字幕、真实素材、动效和最终 MP4。成片固定为 `16:9` 横屏。

`ll-video-edit` 是一个在关键步骤请你查看、确认和修改的 Codex 自动剪辑 Skill。你不需要会写 Remotion 代码；Codex 负责执行，你负责提供真实内容和做关键判断。它支持两种输入：

- **定稿逐字稿**：Codex 制作一条连续配音，再按配音安排画面。
- **已录人物口播视频**：保留原声，人物全程以小窗出现在画面中，再补充字幕、真实录屏和动效；不会自动剪口误或重配音。

## 先看效果

下面是当前素材库中已经确认的“投入累积／资源消耗”动效样片，可直接播放，不需要先下载项目。

https://github.com/user-attachments/assets/5da974ba-c6d4-4db8-80e3-3d4308719bcc

这个视频用于展示素材库中的一种视觉结构。正式成片不会直接剪入预览视频，而是调用模板源码，替换成你当前视频的文字、图片和真实录屏。

## 你需要提供什么

| 输入方式 | 开始时提供 | 声音与人物画面 |
| --- | --- | --- |
| 逐字稿模式 | 已定稿的完整逐字稿 | Codex 生成或接收一条完整配音；不要求人物口播视频 |
| 人物口播模式 | 已录好的带原声人物视频；如有对应逐字稿，也一并提供 | 保留视频原声，核对实际口播转写；人物全程以小窗出现 |

两种模式都要在分镜确定后准备必要的真实截图或录屏。Codex 会先列出可照着执行的素材清单：打开哪个页面、从哪里开始、做哪些操作、画面必须出现什么、录到哪里结束，并标明已有素材和无需你提供的素材。你还需要确认分镜、静态效果图、动态样片和完整初版。

## 它适合谁

- 已经有定稿逐字稿，想把它制作成教程型视频；
- 已经录好人物口播，想保留自己的声音，并在横屏视频里全程显示人物小窗；
- 会使用 Codex，但不会 Remotion 或不想自己写剪辑代码；
- 希望 Codex 帮忙判断每段内容应该使用真实录屏、动效模板还是单次组合画面；
- 希望先看分镜和样片，再生成完整视频；
- 希望最后仍然保留可修改的 Remotion 工程。

它不适合：

- 既没有定稿逐字稿，也没有已录口播视频，希望 Skill 先帮忙写稿或改稿；
- 主要需求是剪人物口误或删除口播停顿；
- 不提供真实录屏，却希望生成虚假的软件操作界面；
- 希望完全不确认，一次性生成无法检查的全片。

## 一条提示词完成安装

把下面这段话直接复制给 Codex：

```text
请帮我安装这个 Codex Skill：https://github.com/liuliu-66-create/ll-video-edit

请按照仓库 README 完成 Skill、动效素材库和运行环境的安装与检查，直到 readyForRendering 为 true。现在只安装和检查，不要开始制作视频；如果需要我操作，请一次只告诉我一个步骤。
```

之后按照 Codex 的提示操作即可。安装过程中需要重启 Codex 时，它会告诉你。

## 开始第一条视频

安装完成后，在 Codex 中输入：

```text
使用 $ll-video-edit 带我制作这条视频。我有一份已经定稿的完整逐字稿，请按六步流程制作；每完成一步先让我查看和确认。
```

如果你已经录好人物口播，改用这段：

```text
使用 $ll-video-edit 把这条已录好的带原声人物口播视频做成 16:9 横屏成片。保留原声，人物全程用小窗；请按六步流程制作，每完成一步先让我查看和确认。
```

把视频作为附件或本地文件路径一同交给 Codex。它会根据你实际提供的材料进入对应模式；如果同时提供逐字稿和视频，会先核对文字与实际口播，不会默默把不一致的稿当字幕。

Skill 固定制作 `16:9` 横屏；你已提供的材料和偏好不会被重复询问。

## 六步会分别得到什么

### 第一步：确认文字和最终声音

逐字稿模式检查完整定稿并生成或接收一条连续配音。人物口播模式检查原视频和原声，转写实际说出的内容供你核对，不自动改稿、删停顿或剪口误。

**你会看到：** 最终文字、声音来源和基础项目信息。

### 第二步：对齐声音并制作分镜

Codex 根据最终声音的时间，把内容拆成镜头，判断每一段应该使用真实录屏、素材库动效还是单次组合画面。口播提到具体 Skill、页面或操作结果时，分镜会标明对应的真实素材。

**你会看到：** 带时间、画面类型、素材需求、模板名称和模板使用次数的分镜表。

### 第三步：准备真实素材

Codex 会根据已经确认的分镜，列出每份素材的状态。需要你录制的部分会写清页面、录制起点、操作顺序、必须出现的画面和录制终点。已提供的口播原片和其他现成素材不会重复索取。

**你会看到：** 录屏和截图清单，以及素材是否齐全的检查结果。

### 第四步：确认静态视觉

Codex 先制作关键镜头的静态效果图。人物口播模式会展示“动效＋人物小窗”，涉及真实录屏时还会展示“实际录屏＋人物小窗”。你可以检查小窗、文字、构图、颜色、遮挡和整体风格，确认后再做动画。

**你会看到：** 关键镜头静态图。

### 第五步：确认动态样片

静态图确认后，Codex 制作带最终声音的动态样片，检查文字出现顺序、动效节奏和录屏衔接。人物口播模式使用原片对应时段的声音。

**你会看到：** 可以直接播放的带声音动态样片。

### 第六步：完成全片并验收

Codex 只补齐尚未完成的镜头，生成完整初版，根据反馈修改，并检查尺寸、声音、字幕、黑帧、内容与画面的对应、人物小窗、遮挡、统一风格和模板使用次数。

**你会得到：**

- 完整 MP4；
- 可以继续修改的 Remotion 工程；
- 本次使用的图片、录屏、最终声音和字幕；
- 技术检查和实际画面验收结果。

## 为什么必须逐步确认

自动剪辑不只是把字幕贴到画面上。分镜判断、真实素材、视觉构图和动效节奏都可能出错。

这个 Skill 把“生成”和“确认”分开：

1. 先确认内容和声音；
2. 再确认分镜和素材；
3. 先看静态效果；
4. 再看动态样片；
5. 最后才生成完整视频。

这样可以在成本较低的阶段发现问题，避免整条视频生成以后才推翻重做。

<details>
<summary>手动安装说明（高级用户）</summary>

如果你熟悉本地环境，也可以展开这里手动安装。

### 1. 下载仓库

克隆或下载整个仓库，并保留完整目录。不要只下载 `skill` 文件夹，因为正式制作还需要仓库中的 `motion-library`。

### 2. 安装 Skill

把 `skill/ll-video-edit` 安装到 Codex Skills 目录。Windows 默认通常位于：

```text
C:\Users\你的用户名\.codex\skills\ll-video-edit
```

### 3. 安装动效素材库依赖

进入本仓库的 `motion-library` 目录，运行：

```powershell
npm.cmd ci
```

### 4. 设置素材库路径

把环境变量 `LL_VIDEO_MOTION_LIBRARY` 设置为本仓库内 `motion-library` 的绝对路径：

```powershell
[Environment]::SetEnvironmentVariable(
  "LL_VIDEO_MOTION_LIBRARY",
  "D:\path\to\ll-video-edit\motion-library",
  "User"
)
```

设置完成后重启 Codex。

### 5. 检查环境

让 Codex 运行：

```powershell
powershell -ExecutionPolicy Bypass -File skill/ll-video-edit/scripts/check_environment.ps1
```

确认输出中的 `readyForRendering` 为 `true`。

</details>

## 当前版本边界

- 当前是公开测试版本，不是一键生成全片的桌面软件；
- 当前 Skill 和动效素材库只支持 `16:9` 横版；
- 真实的软件操作必须来自使用者提供或明确授权获取的录屏、截图；
- 逐字稿模式需要配置配音服务；两种模式都需要 Node.js、FFmpeg、Python 等本地环境；
- README 用于帮助人理解、安装和开始使用，详细执行规则以 [`skill/ll-video-edit/SKILL.md`](./skill/ll-video-edit/SKILL.md) 和 [`references`](./skill/ll-video-edit/references/) 为准。
